# Pack One player-choice disagreement: controlled review protocol

Status: **research only; no production scorer, difficulty threshold, puzzle admission or historical result changes**. This is a preregistered *next-step protocol* created after an exploratory production-data inspection on November 15, 2026. The earlier inspection cannot be used as an untouched confirmation sample.

Tracking: [#1562](https://github.com/killjoy00/mtg-ev-analyzer/issues/1562); implementation in the private Admin Insights review tools. Related public-data research: [context challengers](CONTEXT-CHALLENGERS.md), [context audit](CONTEXT-MODEL-AUDIT.md), [partial-credit plan](PARTIAL-CREDIT-CONTEXT.md) and outcome research #529.

## Questions in priority order

1. **Fixing / land valuation.** When player and model favorites differ between a land and a nonland card, is the relative fixing-versus-spell value appropriate for the *pre-pick pool*? A land card's type line is not enough to infer produced mana or whether the land is good; inspect verified produced-mana metadata and tempo costs before deciding.
2. **Color commitment / legitimate pivots.** Does the existing model overrate a candidate needing unsupported colors or underrate a justified change of lane? Explicit printed mana, all required colors/pips, prior pool and fixing must be assessed. A simple pool-color flag is a prompt for inspection, **not** a castability verdict or off-color penalty.
3. **Card strength / synergy.** Does a model-player disagreement reflect held-out training-only card strength, curve/role/redundancy, or merely preference for recognizable cards? Do not use Pack One votes or final decks as independent card-value labels.
4. **Partial credit.** Does an independently defensible alternative receive low model-only credit, or a weak alternative undeservedly receive high credit? Correct ranking before changing the 0–95 curve.
5. **Puzzle quality.** Only later: do the pre-pick features, rather than votes on the target set, predict genuinely interesting and difficult decisions on unseen sets?

## Frozen sampling rules

The read-only query in `worker/player-model-research-cases.mjs` uses:

- Completed Pacific Daily dates within a maximum 90-day window, current **v10** parent corpus only; no cross-version averaging.
- Browser-observed, non-QA, first encounter per browser player and puzzle; selected card outcomes only; exclude repeats and unobserved choices. Guest identity cannot always uniquely identify a human.
- At least **50** qualifying choices per puzzle, complete candidate/vote mapping, model probabilities totaling within 0.01 of 1, an observed trophy candidate, and no tied leaders. A result set over 1,000 eligible puzzles **fails closed** and needs a narrower date range.
- Separate Latest Set, Mixed and Powered Cube; actual **source pick number** stages P1P1–3, P1P4–6, P1P7+.
- Within each format × stage: at most **six** high-gap disagreements (player favorite differs from model favorite, and the 95% Wilson lower bound on the favorite's human selection share exceeds that card's frozen model probability by at least 0.10). Rank descending by this lower-bound gap, then preference share, number of picks, and stable ID.
- **Three** representative controls from the remaining eligible decisions per cell, chosen with deterministic source-independent ID ordering rather than the observed disagreement score. Do not use a case more than once; never include two questions from the same source draft, even across formats.
- At most 81 cases total. The sample is *deliberately enriched* for disagreement and cannot estimate a population-wide model error rate. The observed player vote percentage is not an independent test of the optimal card.

Both blinded packet and reveal key are generated by the same deterministic algorithm for the same date range. No production player-level data, passwords, raw logs, detailed telemetry, private audit rows or review keys are committed to public GitHub.

## Blinded review

- Authorized reviewers open **Admin → Insights → Research the disagreements → Open blind review** on a narrow, finished date range. Candidate order is deterministic but independent of model support and votes.
- The blind response contains only the public pack cards, source format, actual pick number and prior picks. It **does not include** the model recommendation, the player vote distribution, the trophy pick, case-selection stratum or diagnostic flags.
- Each reviewer privately chooses a **best card** and marks all **defensible alternatives**. Use at least two independently drafted judgments from qualified reviewers before treating any result as grading evidence. Uncertainty and missing metadata must be explicitly recorded in any follow-up benchmark; agreement between two reviewers does not establish a causal win-rate advantage.
- Local browser annotations can be copied, but they are **not written to production**. The separate diagnostic-key request reveals player/model/trophy decisions for post-review analysis. If samples change, reload both views; treat a copied review as tied to its window and corpus.
- The diagnostic flags `land-vs-nonland`, `land-vs-land`, `pool-color-tension`, `nonland-card-value-or-synergy` and metadata unknowns are unconfirmed *review questions*, not error labels.

## Challenger checks and decision rules

**Before running the independent reviewer evaluation, freeze the following comparisons**:

- **Baseline:** frozen v5 / v10 grading policy and raw candidate probabilities, with historical trophy match rule unchanged.
- **Mana challenger:** explicit printed requirements, preserving original source folds and re-fitting contextual statistics only on training complements.
- **Mana + fixing challenger:** as above, plus verified produced mana and cost/conditional availability. Unknown, split/hybrid/Phyrexian/alternative-cost metadata must abstain rather than be treated as zero colors.
- **Card-strength challenger (second stage):** training-only, cross-fitted strength and pre-pick pool/role fit. Keep it separate from mana experiments so attribution is interpretable.

Independent evidence must include source-distinct blinded comparisons and genuine counterexamples (sound pivots, splashes, lands that really are superior). Assess severe **undercredit for reviewer-defensible choices**, severe **overcredit for reviewer-weak choices**, pairwise ranking, missing metadata, and distribution by format, set and pick stage. Fix the model ordering before testing score-curve recalibration. Record all denominators, abstentions, reviewer disagreements and confidence intervals; use source-draft clustering, not hundreds of correlated votes as independent drafts.

For predictive secondary checks, reuse checksum-pinned public 17Lands evaluation machinery and previously frozen train/validation partitions. The existing `research/CONTEXT-CHALLENGERS.md` reports improved held-out *pick prediction* for three representations on most or all confirmation sets, **not** validated grading or win improvement. The old development evidence is already inspected and may not become a fresh confirmation set. Before a new release use genuinely held-out, preferably unseen-set data (no target-set Pack One votes or outcomes for fitting), along with the independent grading gate. Do not spend an untouched test partition through repeated trial-and-error.

**Decision after review**:

- If an explicit-mana or fixing challenger improves blind contextual ranking and holds up in held-out prediction with no material regression, prepare a **separately versioned** model/scoring proposal and standard QA; do not silently replace the current model.
- If rankings are acceptable but partial credit is judged unfair, test a distinct calibration profile on held-out judgments; retain the trophy's 100-point match.
- If observed differences only predict debate/interest, use the learned **pre-pick features** to improve puzzle selection, confirming transfer on an unseen set first.
- If evidence is inconsistent, the decision is **no model change**. Popularity alone never promotes a challenger.

## Operational safety

No migrations or production writes, no Vercel deployments, no automated promotion, no rebuilding user scores, and no raw data in public CI. The protected Admin routes must fail closed for unauthenticated callers. Run the repository's existing required CI, backend gate and signed-in/unsigned-in smoke tests before any guarded Admin release.
