# Mobile build reproducibility

Tracking: #575.

Pack One's native validation and store-candidate workflows use committed dependency and toolchain inputs rather than resolving semver ranges independently on each run.

- `mobile/package-lock.json` is the npm v3 lock generated by the repository's Node 24 GitHub runner from the current `mobile/package.json` dependency ranges.
- `mobile/.node-version` pins Node 24.21.0. The workflow checker also requires npm 11.19.0, the npm bundled on the runner used to generate the lock candidate.
- Mobile validation, iOS archive/TestFlight, Android internal, and Android production-bundle workflows use `npm ci`. A package/lock mismatch is therefore a hard failure instead of silently rewriting dependency resolution.
- `actions/setup-node` caches by the committed mobile lockfile, so cache reuse cannot choose a dependency graph independently of the candidate.

The lock candidate was generated in temporary PR #636 by mobile workflow run 36266601187 and uploaded as artifact `mobile-package-lock`; the temporary PR is evidence only and must not merge. The final PR independently proves `npm ci` on Linux/macOS and both native prebuild/archive paths.

This pins JavaScript/npm inputs, not the full hosted-runner OS image, Xcode version, Android SDK/Gradle remote artifacts, or store-side signing infrastructure. Exact-main RC evidence must still record the source SHA, workflow/run IDs, build numbers, backend revision, and physical-device acceptance.
