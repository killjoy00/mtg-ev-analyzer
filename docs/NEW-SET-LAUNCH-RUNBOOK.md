# Launch a new Pack One set

Open one issue per set. Record each step's evidence there and close it after the first verified public Daily and the first-day monitoring handoff. The agent runs the reviewed workflows and automated checks. The owner approves release or communications when required.

1. **Prepare.** Confirm the Arena date, Scryfall set identity and release date. Register the display name and identify draftable bonus sheets, alternate titles and card faces. Prepare the guide if wanted. Wait for **both** official PremierDraft draft and game archives. [17Lands datasets](https://www.17lands.com/public_datasets) · [Card art](CARD-IMAGE-MAINTENANCE.md)
2. **Validate development.** [Corpus Operations](../.github/workflows/corpus-operations.yml) runs Mondays at 07:23 UTC or by dispatch on reviewed main. Record the set, source URLs and SHA-256s, exact snapshot, development run ID, passing health and a positive gameplay canary for that snapshot. A successful job can also represent an empty discovery or a blocked set. Hold until the [versioned quality gates](../corpus-quality.mjs) pass.
3. **Stage production.** Dispatch Corpus Operations with target `production` and the successful development `validated_run_id`. Confirm both environments have the same Candidate snapshot, source hashes and model. If ingestion inputs changed or the artifact expired, revalidate development first. [Corpus Operations and recovery](CORPUS-OPERATIONS.md)
4. **Prepare selection and display.** Build the [trophy-deck catalog and coverage](../corpus/trophy-decks/README.md) from the imported sources, then the [strength table](../corpus/card-strength/README.md) from the same game archive. Release the reviewed inputs. Run [Score puzzle selection](../.github/workflows/score-puzzle-selection.yml) for this set in development, then production at the same commit. Confirm deck coverage, current strength hash and selection features for eligible picks. Review actual served printings and faces, apply the [guarded image release](CARD-IMAGE-MAINTENANCE.md) when needed, and verify matching names and art on the deployed API.
5. **Activate and smoke-test.** Require passing health under seven days old for the exact snapshot. Activate development and wait for serving readiness. Run [activation smoke](../.github/workflows/corpus-activation-smoke.yml) with the expected snapshot. Verify Custom Practice, reroll, and the actual Easy/contested selection and fallback behavior for Latest and Mixed against the [Daily policy](LATEST-DAILY-SELECTION.md). Repeat in production after both current Pacific-date schedules are pinned and comfortably before the next midnight. If activation committed but readiness failed, retry the readiness operation.
6. **Verify the public day and close.** For the newest regular set, confirm eight Latest picks, at least two Mixed picks, and the new season starting on the first new-set Latest date. Players can create schedules before the 00:07 Pacific trigger. Preserve existing schedules, scores and shares. Check a public run, result/share and prior game, then update Practice, publish any [approved guide](SET-GUIDES.md) or communications, and record first-day monitoring.

For a quality or identity failure, hold the set and fix the cause or wait for changed archives. A later upstream revision gets its own immutable Candidate. Use Live → Paused if new starts must stop. Keep Traditional Draft admission and model changes on their own release paths.
