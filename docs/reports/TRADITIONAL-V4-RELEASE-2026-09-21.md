## Operational lifecycle for future component releases

For reviewed supplemental puzzle components, the safe release order is:

1. Stage in development as Candidate.
2. Verify the exact staged artifacts and preservation checks.
3. Explicitly publish in development. Components whose parent is Live become Live; components under Candidate parents remain Candidate.
4. Stage the same exact artifacts in production as Candidate.
5. Verify production staging and preserved corpus.
6. Explicitly publish in production. The workflow requires matching development publication eligibility before production mutation.
7. Run post-publication preservation, serving-quality and any source-specific verification.

Do not bypass the development-publication prerequisite. A production publish request seeing a development Candidate under a Live parent must fail closed.

## Serving semantics

Traditional v4 is not a separate game mode and does not replace Premier.

For each eligible regular set, Live Traditional v4 decisions are supplemental inventory inside the same normal Draft Run serving universe as retained Premier decisions, subject to the ordinary set, pick, difficulty, source-uniqueness, score-floor and Daily/custom-practice rules.

Powered Cube remains its own environment. Its Traditional v4 inventory is restricted to P1P2-P1P7 and joins the Powered Cube serving pool only.

Candidate components never enter current new-game membership. Historical games continue to resolve pinned puzzle/component IDs even if current publication status later changes.
